The second public alpha of MothRef. Saving no longer makes boards grow, the default full-resolution mode uses about half the memory, and the board gets drawing tools, lists and checklists. This is the first release with installers for every platform.

### New

- **Pen, Marker and Arrow** in the bottom toolbar. Strokes are editable vector items, appear in PNG, SVG and PDF exports, and take their color and thickness from Settings › Canvas and navigation. CLI: `stroke`.
- **Label, Note and List** replace the single Insert text. The note editor is roomier, formats selected lines, and supports headings, bulleted, numbered and nested lists and checklists. Enter continues a list, Shift+Enter adds a line inside an item, Tab changes the level, Ctrl/⌘+Enter saves. Checkboxes toggle right on the canvas.
- **Group by folder.** Right-click › group loose images by the folder they came from, or turn on automatic grouping in Settings › Adding. CLI: `group-origin`, `add --group-origin`.
- **Dragging places freely by default.** Snapping to other items and its alignment guides are now off until you turn them on in Settings › Canvas and navigation; snapping to the grid is unchanged.
- **Snap to points** moved to the canvas context menu and the selection More menu, with the grid spacing next to it; Shift bypasses snapping while dragging. CLI: `snap-grid`.
- **Installers:** Windows setup wizard, macOS DMGs, Linux AppImage, DEB and RPM, Linux ARM64 builds, and an Arch package with its build recipe.

### Improved

- **Boards no longer grow on every save.** Each save used to append the whole layout and the library preview (about 50–100 KB) and kept old copies until the file was twice the size of its images. A save now rewrites the layout right after the images and cuts the file there, so moving or editing items leaves the file the same size. Removed images are compacted away once they pass an eighth of the board. Saving also repairs a damaged tail after the images.
- **Less memory in full-resolution mode.** Detail tiles no longer reserve unused mip levels (−25% video memory), and image uploads go to the GPU in 16 MiB batches, so temporary upload buffers stop leaving holes in video memory. On shared-memory graphics (most laptops) this was process memory: a 150-photo board went from 3.48 GB to 1.87 GB on reopening.
- **Faster opening on Windows and ext4.** The private recovery copy of an opened board is made by the operating system instead of reading, hashing and rewriting every image; on APFS and Windows Dev Drives the copy is a clone.
- AVIF decoding moved to `avif-decode` 3 with `rav1d`. Notes size to their canvas font. The moth icon has a thicker, darker outline that stays readable on the light theme.

### Fixed

- View mode keeps groups, titles, notes and the selection visible; the images-only filter now belongs to Over mode.
- Drawing sessions keep the mini window's size when skipping to the next image.
- The recovery lock is released when a board closes, even if a child process inherited its file handle.
- The CLI applies journal-confirmed changes the same way as the window: a batch with a refused command still applies the rest, an import starts from an empty board, and a recovered board counts as unsaved.

### Coming in the next release

- **Automatic updates:** MothRef will check for a new version, download it and install it from the app.
- **What's new window:** after an update, a window will show what changed in the new version.

### Validation

- Formatting and workspace Clippy with warnings denied pass on Linux, Windows and macOS in CI, as does the full test suite.
- Saving: a new test keeps the file size fixed across saves after moves; the in-place layout rewrite reads as the saved board at every torn byte; 50 save process kills lost no acknowledged save; `xtask killtest 50` and `load-killtest 20` lost no acknowledged commands.
- Memory was measured on Linux with software rendering, where video memory is process memory as on shared-memory adapters. Not yet measured on Windows hardware.
- Not checked by hand yet: the new installers and packages on each system.

### Compatibility and limitations

- Boards are saved as **schema 11** (vector strokes and formatted notes). Older boards open and are upgraded on the next save; **earlier MothRef versions cannot open schema-11 boards**.
- Source builds on x86 need NASM.
- Binaries are unsigned and macOS builds are not notarized.
