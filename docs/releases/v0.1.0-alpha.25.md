This preview adds selectable app icons and static AVIF images on reference boards.

### Changes

- The moth holding a gallery is the default app icon. Settings › Appearance › Application icon offers the engraved, Photocraft-style alternative and remembers the choice across launches.
- App marks now appear in the titlebar, native windows, the Windows executable, the macOS app bundle and Dock, and the Linux desktop launcher. macOS and Linux also include icons for `.moth` board documents. Linux archives contain desktop integration files and `DESKTOP.md` with installation commands.
- Add static AVIF images by opening, dropping or pasting files. Boards retain their AVIF originals; previews, full-resolution tiles, baked caches and original exports support the format, including transparency and high-bit-depth input converted to the existing 8-bit display pipeline.
- AVIF headers are checked before decoding, including container box boundaries, every AV1 sequence header and the alpha plane. Whole-frame decoding uses the existing memory admission gate and bounded shared-frame cache.

### Validation

- Final serial workspace run: **431 passed**, **12 failed because of sandbox restrictions**, **3 optional measurements ignored**. All AVIF, icon-choice, allocation and headless-rendering checks passed. The twelve incomplete platform checks require local sockets, D-Bus or native Wayland file-descriptor operations that the sandbox denies; they remain enabled in CI.
- An earlier parallel run encountered a transient snapshot file lock. The isolated rerun and the final serial run passed that check.
- Formatting, workspace Clippy with warnings denied, full dependency checks against the available advisory database, and Android-core compilation passed. All **34** image/board corpus fixtures validated, including the two new AVIF samples.
- Image-reader fuzzing found malformed top-level and nested AVIF boxes reaching debug assertions in the external parser. Added bounded structural validation and regression tests. The final sandboxed run completed **4,203 executions in 91 seconds** without a decoder crash, peaking at **479 MiB RSS**. LeakSanitizer then failed because the sandbox forbids its ptrace-based inspection, so the overall fuzz check remains **incomplete**.
- Quick release benchmark on llvmpipe: 10,000 distinct images, 100 frames, p99 **86.550 ms**, **13.32 MiB** of textures. 4K JPEG tile medians: **19.086 ms** without cache and **0.057 ms** from memory cache. These software-adapter timings do not establish hardware performance or a regression comparison.
- Workflow YAML, embedded macOS packaging Python, the Linux desktop entry and MIME XML validated locally. Native Explorer/Finder launch and icon switching remain unverified locally.

The release workflow requires all four binary builds and the release commit's CI checks to pass before publication.

### Compatibility and limitations

- AVIF accepts static images up to 32 Mi pixels, 128 MiB of compressed input and 8 MiB of container metadata. Animated AVIF is unsupported. Container-level crop/rotation and color-profile interpretation are not added by this release.
- The installed launcher and board-file icons retain the default moth. Wayland taskbar icons follow the installed launcher; the setting explains this desktop limitation. Native Windows/macOS interaction remains unverified locally.
- Boards continue to use schema 8; earlier MothRef versions cannot display AVIF originals.
- Building requires Rust 1.98, CMake and a C/C++ toolchain. x86 builds also require NASM 2.16.x; workflows pin 2.16.03 because libaom 3.11's build scripts reject NASM 3's changed help output. libaom is statically linked; users do not need to install a system codec.
- Binaries are unsigned and macOS builds are not notarized. Tier-3 reliability checks remain CI/maintainer-only.
