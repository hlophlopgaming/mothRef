MothRef's fifth downloadable preview focuses on loading speed and memory
behaviour on large boards, plus a configurable image cache.

### Included

- Configurable image-cache settings: an available-RAM allowance (1–50%),
  automatic adapter limits, or a manual 32–512 MiB ceiling, applied immediately
  with a reset-to-defaults option. English and Russian explanations cover what
  evicting previews means.
- The GPU image cache now grows by actual texture-page bytes instead of image
  count, capped at one eighth of available RAM plus reclaimable pages and the
  existing adapter ceilings. RAM is sampled in the background during activity and
  LRU pages are evicted when memory becomes scarce.
- Area-preview accumulation is specialized by pixel format and reuses already-
  sized decoded images, preserving alpha-weighted pixels, mip quality and decode
  budgets.
- Progressive board loading: journaled image batches appear while a board is
  still loading, overlapping preview decoding with storage. Editing and saving
  stay blocked until loading completes, and errors preserve partial loads as
  unsaved boards. Healthy `.moth` files are read through their footer chain while
  checksum verification and corruption recovery remain intact.
- Image originals are read directly from recovery-journal ranges when opening
  boards and importing BeeRef/PureRef files, removing duplicate `.source` copies
  and their rereads while keeping journal-before-acknowledgment durability.

### Downloads

- Windows x86_64: extract the ZIP and run `mothref.exe`.
- macOS: use `macos-arm64` for Apple Silicon or `macos-x86_64` for Intel; extract
  and run `mothref` from Terminal.
- Linux x86_64: extract and run `./mothref`. Ubuntu 24.04 or a compatible newer
  distribution, X11/Wayland libraries and a working graphics driver are required.
- `SHA256SUMS` accompanies the four archives. Use `--software` for the fallback adapter.

### Preview limitations and validation

This remains an experimental preview. Keep separate copies of important boards
and original references. The full milestone/release reliability gates are not
claimed complete.

- One sequential, disk-backed comparison on the 29-image `hardPics.moth` fixture
  measured first-preview latency falling from ~629 ms to ~90 ms (~7× faster) and
  all-preview latency from ~1036 ms to ~668 ms (~1.55× faster) under the same
  llvmpipe adapter. This is a single comparison, not multi-run statistics,
  native-window latency or large-board performance; see `docs/LOAD-PERFORMANCE.md`.
- No `.moth` format or schema change: boards remain schema 4, with schemas 1–3
  still readable. Undo history is not restored after reopening.
- Binaries remain unsigned; macOS builds are not notarized. Native Windows/macOS
  manual checks, long reliability runs and idle-machine performance qualification
  remain pending.
- Workspace tests, clippy and formatting passed before release preparation.
