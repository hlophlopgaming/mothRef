This preview takes images up to 100 megapixels at full detail, replaces the last bare windows with dialogs and panels in the app's style, picks colors from the whole screen, and adds a handful of everyday settings.

### Changes

**Large images**

- Images up to 100 megapixels (for example 12,000 × 8,334) are added at full resolution and keep every pixel when zoomed in; the limit was 32 megapixels. Originals up to 256 MiB are accepted (was 64 MiB), WebP up to 100 megapixels (was 2).
- Zooming into a very large WebP is several times faster and uses a fraction of the memory: the whole frame is decoded once for the preview, every tile batch and the tile bake, instead of once per batch (an 81-megapixel WebP: first zoom 17.9 s → 1.9 s on the test machine).
- Optional: Settings › Adding › Reduce very large images when adding — Never (the default), or to 4096 or 8192 px on the longer side. The file on disk is never changed; a JPEG stays a JPEG.

**Dialogs and panels**

- Export is a dialog that says what each export gives and asks where to save in the system “Save as” dialog; there is no path to type.
- Edit selection, Arrange options and Image pickers open as panels at the right edge, with a title and a close button; several stack instead of overlapping.
- Open original in viewer no longer opens an empty window on the board: a short notice says it is opening, then that it opened or why not. On Linux, `gio open` and `kde-open` are tried when `xdg-open` is missing.
- The Settings window and the “Save as .moth to continue” prompt after opening a .bee or .pur board have the same dialog look as the rest of the app.
- Pasting with nothing usable on the clipboard says so in a notice above the bottom toolbar.

**Pickers**

- The color picker takes colors from anywhere on the screen: on X11 and Windows press on the board and drag outside the window (the panel shows the color under the pointer, releasing copies it); on Linux (including Wayland) and macOS, Image pickers › Pick a color from the screen… opens the system picker.
- The coordinate picker lists image, pixel, original size, file format and size, size on the board and selection size, and answers at once even on a 100-megapixel image.

**Settings and starting**

- Settings › General › Open the last board on start, and Settings › Adding › Bring clicked images to the front (both off by default).
- `mothref board.moth a.png b.jpg` opens the board and adds the images once it has loaded; further boards open in tabs.
- Settings › For developers shows the recent log with a warnings-and-errors filter and a Copy button.
- Drawing sessions: saved plans and the last setup survive a restart; the mini session window can be moved and resized with a stylus on Wayland; session summaries open full screen; image detail in sessions is preserved.

### Validation

- Formatting and workspace Clippy with warnings denied passed; the full workspace test run passed (393 tests) and all 30 corpus fixtures passed.
- Tier-2 checks for the areas touched: `cargo xtask killtest 50` (no acknowledged command lost); `image_reader` fuzzing for 90 s from `corpus/images`, now including image reduction (no crash); `cargo xtask bench --quick` against `main`, alternating runs: frame p99 and cached tile time unchanged, uncached 4K JPEG tile median 10.45 ms vs 10.2 ms (within noise, below the 10% limit).
- Large-image zoom probes for PNG, JPEG and WebP at 81–100 megapixels are recorded in docs/LOAD-PERFORMANCE.md (test container, not reference hardware); `xtask large-inputs` makes the inputs reproducible.
- Checked on a nested KDE Plasma 5.27 session: the export dialog, the three panels, Settings, the conversion prompt, the empty-paste notice, Open original (opened and failed), the coordinate picker on a 100-megapixel image, image reduction, command-line board plus images, and the screen color picker by drag through XWayland. CI passed on Windows and macOS for every change.

### Compatibility and limitations

The board format is unchanged: schemas 1–6 remain readable. The system “Save as” dialog for exports, the desktop-portal color picker (GNOME and Plasma on Wayland), the screen color picker on Windows and `NSColorSampler` on macOS were not shown in the test session; notes for native checks are in docs/M2-EDITING-VALIDATION.md. Very large images need memory: a 100-megapixel WebP keeps one 400 MB frame while it is being zoomed.

Binaries are unsigned; macOS builds are not notarized. Native launch, window transitions, HiDPI, device loss with several windows and real-hardware glass blur remain incompletely qualified; see docs/M3-WINDOW-VALIDATION.md. Tier-3 reliability checks remain CI/maintainer-only; the five-minute soak is reserved for release 1.0.
